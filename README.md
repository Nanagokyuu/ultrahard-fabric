# Ultra Hard（超困难）

适用于 **Minecraft 26.2** 的 Fabric + Kotlin 模组。新增真正的难度枚举值 **Ultra Hard（超困难）**，与和平/简单/普通/困难并列，基于困难并附加更严苛规则。

## 依赖

请一并安装：

- [Fabric Loader](https://fabricmc.net/use/) ≥ 0.19.5
- [Fabric API](https://modrinth.com/mod/fabric-api)（`0.160.0+26.2` 或更高的 26.2 兼容版本）
- [Fabric Language Kotlin](https://modrinth.com/mod/fabric-language-kotlin) ≥ `1.13.12+kotlin.2.4.0`
- Java 25+

## 安装

1. 安装 Fabric Loader（Minecraft 26.2）。
2. 将本模组 jar 与上述依赖放入 `.minecraft/mods`。
3. 启动游戏。

## 构建

需要 **JDK 25**。

```bash
./gradlew build
```

产物位于：`build/libs/ultrahard-1.0.0.jar`（不含 `-sources`）。

## Kotlin 代码结构

Kotlin 源码位于 `src/main/kotlin/com/nanagokyuu/ultrahard/`，与 Java 一样按职责分包，子目录与包名对应。根目录保留初始化入口 `UltraHardMod` 和供 Java Mixin 调用的 AI 门面 `UltraHardAi`。

- `ai/`：目标选择、远程和世界环境 AI；`ai/combat/` 存放近战通用战术与特殊兵种战术。
- `config/`：配置模型 `UltraHardConfig`、加载与迁移 `UltraHardConfigs`、数值校验 `UltraHardConfigValidation`。
- `difficulty/`、`enchantment/`、`equipment/`：难度、附魔和装备规则。
- `events/`：`UltraHardEvents` 注册事件、处理伤害和饥饿；`UltraHardKillStreak` 管理连击；`UltraHardLifesteal` 结算吸血；`UltraHardSleep` 结算睡眠治疗。
- `raid/`：袭击参与者奖励及离线奖励存档。
- `rules/`：`UltraHardRulesBook` 发放规则书，`UltraHardRulePages` 按当前配置生成分主题书页。

## 启用超困难

与原版难度相同，可在以下位置选择：

### 创建新世界（开始游戏）

在「创建新世界」→ 游戏选项页的 **难度** 循环按钮中，与和平 / 简单 / 普通 / 困难并列出现 **超困难 / Ultra Hard**。选中后会写入世界的 `LevelSettings` / `WorldData`（序列化键为 `ultrahard`），开局即为超困难。

### 游戏内命令（需要权限等级 2 / OP）

```text
/difficulty ultrahard
```

也可使用 `/difficulty peaceful|easy|normal|hard` 切回其它难度。

### 游戏内选项菜单

在世界选项中的难度循环按钮里选择 **超困难 / Ultra Hard**。

## 效果说明（服务端权威）

当世界难度为 **Ultra Hard** 时（以下数值为默认配置）：

1. **基于困难**：原版 Hard 相关行为均生效（僵尸增援、蜘蛛增益、饥饿致死等）。
2. **无自然回血**：取消饱食度/饱和度带来的自然恢复（类似 `naturalRegeneration false`）；药水等其它治疗仍可用。
3. **饥饿加快**：玩家饥饿值消耗（exhaustion）默认 × 1.25；连续超过两个游戏日没有进食后提高到 × 1.75。
4. **动态护甲伤害**：敌人伤害根据玩家受击瞬间的护甲值连续增加；每点护甲增加 4% 原始伤害，最多按 20 点护甲计算，因此满钻石甲和满下界合金甲均为 × 1.8。背包装备不计入，换装立即生效；末影龙、凋灵和监守者始终保持原版伤害。
5. **敌对生物攻击软上限**：友好生物和 PvP 不受影响。攻击敌对生物时，伤害达到其最大生命值的 25% 后，超出部分保留 50%，最终向下取整。例如 20 点生命的怪物，9 点伤害会变为 7 点。触发时会显示特殊粒子。
6. **装备耐久减半**：工具、盔甲和盾牌的有效耐久减半，即每次耐久消耗翻倍；金制工具与金制盔甲不受影响。
7. **袭击八波**：最终波基础阵容为 4 个掠夺者、4 个卫道士、2 个女巫、2 个唤魔者、3 个劫掠兽，另有骑乘单位。第八波期间在任意存活的最终波袭击单位 64 格内累计停留 100 游戏刻（5 秒）的玩家获得奖励资格；不要求最后一击，创造和旁观不计。胜利后每人获得吸血 III 附魔书，以及附魔金苹果或不死图腾之一，默认各 50%。
8. **睡眠恢复**：按主世界昼夜日期，每昼夜最多治疗一次，连续睡眠至少 5 秒（100 游戏 tick）才结算。治疗量默认为最大生命值的 40%，并限制在 6～12 点之间；跳夜沿用原版人数规则。误触床或提前起床不会消耗治疗次数，中途起床后重新计时。

### 前期恢复道具

超困难新增两种不依赖自然回血的恢复道具。它们仅在超困难模式生效，且持续治疗不能与另一种恢复效果叠加。

- **简易绷带**：三张纸横向排列，羊毛放在中间纸的上方或下方，合成三个；任意颜色羊毛均可。使用需持续 3 秒，之后在 8 秒内恢复 4 点生命值。有效伤害会中断使用和剩余治疗；读条完成前中断不消耗绷带，完成后已经消耗，剩余治疗被打断不会返还。最多堆叠 16 个。
- **滋补汤**：一个碗、任意一个熟肉和任意两个蔬菜合成。使用需持续 3 秒，之后在 12 秒内恢复 8 点生命值；每分钟最多成功使用一次，使用后返还空碗。滋补汤不可堆叠。
- 两种道具都不能在满血时使用；绷带和滋补汤都要求玩家脱离持续受击，适合战斗间隙而不是硬扛伤害。
- 完全格挡或未生效的伤害不会打断治疗。滋补汤成功使用后补充 8 点饥饿值；持续治疗被打断不返还材料、不重置冷却，重登、重启和重生也不能刷新其冷却。受伤中断使用读条的规则仅针对绷带。
- 简易绷带会额外出现在奖励箱、地牢、废弃矿井、神殿、雪屋、掠夺者前哨、沉船、海底废墟、埋藏宝藏、废弃传送门和要塞等多种原版宝箱中；开局奖励箱固定追加 3 个。

### 吸血附魔

- 可附加在剑和斧上，最高正常等级为 III，且不与其它附魔冲突。
- I / II / III 分别将本次攻击经过护甲减免后的伤害的 20% / 30% / 40% 转化为玩家生命值；IV 级为 50%，之后每级增加 10%，IX 级达到 100% 后不再增加。
- 本次攻击伤害仍受 Ultra Hard 的软上限限制：超过目标最大生命值 25% 的部分保留 50%。
- 吸血仅对敌对生物的满蓄力直接近战命中生效，按有效伤害与吸血比例计算回复量并保留小数。每秒最多触发一次，同一 tick 攻击多个敌人时取最大有效治疗量。例如实际造成 6 点伤害时，I / II / III 分别恢复 1.2 / 1.8 / 2.4 点生命。治疗直接触发原版生命值图标的回复跳动效果。
- 沙漠神殿宝箱会额外尝试生成吸血附魔书：I 级 5%、II 级 4%、III 级 3%。
- 可通过 `/give @p minecraft:enchanted_book[stored_enchantments={levels:{"ultrahard:lifesteal":4}}]` 获取 IV 级；将等级数字改为更高值即可获取更高等级。

### 战斗连击与敌人 AI

9. **战斗连击**：当前生命改为累计战斗经验。普通敌对生物按最大生命值计入，每 1 点生命值获得 1 点经验，单次击杀最多获得 100 点；击杀末影龙、凋灵或监守者固定获得 1000 点。累计 2000 点经验后封顶，敌人伤害最低为 0.75 倍；它与护甲倍率相乘，而不是把所有敌人的最终伤害直接设为 0.75 倍。每累计 200 点经验在物品栏上方显示进度和修正，并播放粒子。
10. **敌人装备**：Ultra Hard 下敌人生成护甲的概率为原版的 1.5 倍。
11. **敌对生物战术 AI**：
   - 僵尸会从目标身后包抄；同一目标附近有两只以上僵尸时会前后夹击，未持武器者会为持武器者让出前排。
   - 仇恨、装备和距离联合决定目标，默认搜索 32 格。装备分为每件皮甲 1、锁链甲 2、铁甲 3、金甲 2、钻石甲 4、下界合金甲 5；主手或副手持盾加 3 分，双持只计一次，不要求举盾，背包不计。其它未列出的护甲暂计 0 分。创造和旁观玩家不参与，新目标需可见，近战优先排除不可达目标。
   - 每只怪物独立记录玩家造成的最终伤害（含玩家投射物）：每点伤害增加 2 仇恨，上限 40，每秒衰减 1；30 秒未攻击、死亡、离线或换维度后清理。默认目标优先级为 `仇恨 + 近身反击加分 + 当前目标加分 - 装备分×0.6 - 距离×0.35`，最高者优先。3 秒内伤害过该怪物且当前距离不超过 4 格时反击加 6 分，当前选定目标加 2 分。
   - 新目标锁定 3 秒，死亡、离开范围或不可达会提前解除；锁定结束后，候选优先级至少高出当前目标 4 分才切换。同分按距离和 UUID 稳定选择。重甲玩家可以通过输出吸引火力；女巫优先治疗受伤袭击单位。
   - 玩家举盾时优先绕行。落点不可站立、路径不可达、连续 3 秒没有绕后进展，或总计 6 秒仍未完成时，近战和远程单位按原有规则施压。苦力怕面对举盾玩家时最多尝试绕到身后两次；两次均失败后不再取消引爆，直接爆炸。
   - 骷髅通常维持至少 4 格距离并使用更高精度的箭；有可用路线时先绕盾再射击，狭窄地形中保持正面射击。
   - 苦力怕开始引爆后，附近敌对生物会撤离爆炸范围；蜘蛛命中玩家后会在其脚下生成持续约 6 秒的临时蛛网，同一玩家的蛛网触发有冷却时间。
   - 末影人会在玩家直视或正面举盾时，尝试瞬移到玩家视线后的安全位置；蠹虫会分配正面牵制和侧后方包围位置，末影螨会高速侧移骚扰。
   - 女巫保持后排，优先治疗受伤的掠夺者、卫道士、唤魔者和劫掠兽；玩家接近时依次投掷虚弱、缓慢和伤害药水。
   - 敌对生物的互相伤害不会导致目标转移；亡灵白天寻找可达的水源或阴凉处。AI 默认每 10 tick 更新一次，同批怪物按实体编号错峰计算。装备分缓存 5 tick，同目标僵尸共享 10 tick 编队快照；避阳落点及失败结果缓存 5 秒，单次最多尝试 8 条路径。近战目标可达性成功缓存 1 秒、失败缓存 3 秒；包抄失败后退避 2 秒再重试，目标变化或明显移动可提前重查。

### 护甲与连击如何叠加

默认公式（先调整输入伤害，再由原版计算护甲等减伤）：

```text
护甲倍率 = 1 + min(0.8, min(当前护甲值, 20) × 0.04)
战斗经验 = min(当前生命累计经验, 2000)
战斗经验倍率 = max(0.75, 1 - 战斗经验 × 0.000125)
调整后的输入伤害 = 原始输入伤害 × 护甲倍率 × 战斗经验倍率
```

| 当前护甲值 | 0 经验 | 400 经验 | 1200 经验 | 2000+ 经验 |
|---:|---:|---:|---:|---:|
| 0 | 1.00 | 0.95 | 0.85 | 0.75 |
| 15 | 1.60 | 1.52 | 1.36 | 1.20 |
| 20 | 1.80 | 1.71 | 1.53 | 1.35 |

- 玩家本人或玩家投射物造成敌对生物死亡才计入经验；普通怪物按最大生命值计入且单次最多100点，末影龙、凋灵和监守者固定计入1000点。宠物击杀、纯环境死亡、友好生物和 PvP 不计。
- 真正死亡（包括 `/kill`）清零，超困难下会显示本次战斗经验与减伤总结；不死图腾成功救回不清零。
- 服务端每 tick 检查在线玩家：进入创造/旁观，或当前难度不再是超困难时清零。正常重登和换维度保留存档经验，但仍受这些检查约束。
- 清零仅使**战斗经验倍率**恢复 1.0；护甲倍率不会因此恢复为 1.0。末影龙、凋灵和监守者不应用这两项伤害倍率修正，但击杀它们仍会提供固定战斗经验。

### 袭击奖励与存档边界

已在胜利时结算的待领取奖励保存于主世界存档。在线玩家直接领取；离线者下次在超困难难度上线时领取。背包满则掉落脚下。

最终波参与时长、参与者名单以及袭击实例的发奖标记保存在内存中，战斗中重启会丢失尚未结算的参与记录。只有已经排入待领取队列的奖励支持重启后领取。

## 游玩重点

超困难不是单纯提高怪物生命值，而是把资源管理、战斗节奏和走位都变成长期压力：

- **按当前护甲规划战斗**：护甲值越高，敌人伤害倍率越高；满钻石甲和满下界合金甲均为 1.8 倍。连续击杀会逐步降低敌人伤害，死亡或切换到创造/旁观会失去本次生命的战斗收益。
- **兼顾爆发与持续输出**：对敌对生物的单次伤害有软上限，超过目标最大生命值 25% 的部分保留 50%。
- **盾牌不是绝对安全**：敌人会判断举盾状态并绕后，骷髅和远程敌人尤其需要利用地形、拐角和高度差。
- **保持移动空间**：蜘蛛网、苦力怕疏散、末影人绕后和亡灵避阳都会改变战场位置；狭窄地形通常会放大这些机制的威胁。
- **把睡眠当作有限资源**：每昼夜只能治疗一次，连续睡满 5 秒后恢复最大生命值的 40%（默认限制在 6～12 点）；睡眠治疗不影响原版跳夜。
- **用输出保护队友**：装备分不是唯一仇恨来源，主动攻击可以吸引怪物；站得太远或无法接近也会降低目标优先级。
- **优先处理袭击支援单位**：女巫会治疗受伤的袭击单位，第八波还会同时出现多种远程单位、近战单位和骑乘劫掠兽。

## 游戏内规则书

首次在 Ultra Hard 世界中进入游戏时，每位玩家会获得一本「超困难规则」。规则书会根据当前配置显示睡眠治疗、饥饿倍率、敌人伤害倍率和第八波数量等数值；如果背包已满，书会掉落在玩家脚下。每位玩家只会获得一次，数据会随玩家存档保存。

## 配置

当前生命战斗经验和每日睡眠治疗次数会随玩家存档保存；死亡、离开超困难、进入创造或旁观会清空战斗经验。规则书是领取时的配置快照，不会随配置变化自动更新。

首次启动后会生成 `config/ultrahard.json`。`armorDamageScaling` 控制护甲值带来的伤害增长速度，`maximumArmorDamageBonus` 控制额外伤害上限；`killDamageReductionPerExperience`、`killDamageExperienceCap`、`killDamageMinimumMultiplier`、`killDamageExperienceMilestone` 控制战斗经验减伤；`sleepHealingFraction`、`sleepHealingMinimum`、`sleepHealingMaximum` 控制睡眠治疗。仇恨搜索范围、每点伤害仇恨、衰减、上限、装备和距离权重、切换差值、目标锁定时间均可配置；装备基础评分、缓存时长和绕行/施压时长为固定规则。

配置加载会逐项检查类型、整数要求、有限数和范围。非法字段仅在内存中回退默认值，日志注明字段和原因，磁盘保留原值供排查，其余合法设置不受影响。AI 更新间隔至少 1 tick，避阳搜索半径最多 16 格，目标搜索半径最多 64 格，普通距离/搜索半径最多 64 格，导航速度最高 4 倍，概率和伤害折算比例限制在 0～1；袭击波次为 1～8，各最终波兵种最多 128 个。宝箱奖池总权重为零时整组回退默认值。新增字段仍自动补齐。

修改该文件后重启游戏或服务器即可生效。配置由服务端判定，联机玩家不需要单独修改。

### 主要配置项

| 配置项 | 默认值 | 作用 |
|---|---:|---|
| `armorDamageScaling` | 0.04 | 每点护甲带来的额外输入伤害倍率 |
| `maximumArmorDamageBonus` | 0.8 | 护甲额外倍率上限 |
| `killDamageReductionPerExperience` | 0.000125 | 每点战斗经验降低的伤害倍率 |
| `killDamageExperienceCap` | 2000 | 参与倍率计算的战斗经验上限 |
| `killDamageMinimumMultiplier` | 0.75 | 战斗经验倍率下限 |
| `killDamageExperienceMilestone` | 200 | 粒子和物品栏上方提示的经验间隔 |
| `sleepHealingFraction` | 0.4 | 睡眠恢复的最大生命值比例 |
| `sleepHealingMinimum` / `sleepHealingMaximum` | 6 / 12 | 睡眠治疗量上下限；最小值不要大于最大值 |

已有合法配置会保留。若希望使用本文中的默认数值，请对照上表检查配置，并在修改后重启游戏或服务器。

## 验证与回归

构建会自动执行 `verifyMixinConfiguration`，检查点分类名、重复注册及源码与注册列表的一致性；可用 `./gradlew verifyMixinConfiguration` 单独执行。Mixin 列表使用 `accessor.RaidAccessor` 这样的相对类名，不使用 `accessor/RaidAccessor` 文件路径。

```bash
./gradlew clean build
git diff --check
```

当前仓库没有自动化测试用例，构建成功不等于完成游戏内行为测试。发布前建议在独立测试世界验证：

- 裸装、15 点护甲、20 点护甲与 0/200/1000/2000 战斗经验的倍率组合；首领攻击不受护甲动态倍率和战斗经验倍率影响。
- 每 200 战斗经验的 Action Bar 和粒子；默认经验在 2000 封顶，之后不再累计或产生新的节点提示。检查死亡、图腾、模式/难度切换后的经验。
- 重登、换维度、正常重启后玩家数据是否保留。
- 睡眠不足/达到 100 tick、同日重复睡眠及多人跳夜前的治疗结算。

- 绷带读条受伤、完成后受伤、完全格挡，以及汤的治疗中断和跨重登冷却。

## 崩溃排查

### 加载世界时报 RaidAccessor / IllegalClassLoadError

已修正 `ultrahard.mixins.json` 中把类名写成斜杠路径的问题。访问器虽然列在配置里，但错误的名称会导致注册名称与运行时类名不一致，加载袭击数据时出现 `The mixin is missing ... and the mixin has not been applied`。所有 Mixin 条目现统一使用点分类名，不仅修复 `RaidAccessor`，也覆盖 `RaidRaiderTypeAccessor` 等其它条目。

重新构建后退出游戏，用 `build/libs/ultrahard-1.0.0.jar` 替换实例 `mods` 中的旧版本，避免同时保留多个 Ultra Hard jar；不要安装 `-sources.jar`。先备份存档，再在测试世界验证创建、重载及袭击。该错误不需要通过删除世界或修改袭击存档来处理。

### gldCopyBufferSubData: NEEDS IMPLEMENTATION

单独的 `UNSUPPORTED (log once): gldCopyBufferSubData: NEEDS IMPLEMENTATION` 提示不足以确定另一个崩溃原因。本次提供的致命异常链明确指向服务端袭击数据初始化期间的 Mixin 类加载错误，因此不把这条图形提示作为本次修复对象。若替换 jar 后仍有崩溃或画面异常，请同时保留完整 `latest.log` 与新的崩溃报告，继续按新的异常链排查。
